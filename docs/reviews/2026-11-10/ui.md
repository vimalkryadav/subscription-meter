# UI/frontend council review

Reviewed released commit `596d7f7d187d0e9eeb72cfeafb8f322bd8bce00f`, 2026-11-10. Read-only source review and isolated authenticated browser context against live release. No mutations, inference requests, raw capture detail, exports, screenshots, credentials or user identities retained. Browser context closed; shared browser left running. Effort: S approximately 0.5–1 day, M approximately 2–4 days, L approximately 5+ days including verification, not commitments.

## Ranked findings

1. **P1 / M–L: Native Windows onboarding is absent.** Confirmed source: `frontend/src/shared/ConnectionSetup.tsx:20–27` renders POSIX shell/curl/Python commands and labels macOS/Linux only; `frontend/setup/setup-claude.py:5,24,36,75` uses fcntl, Unix ownership, chmod and shell launchers. Native Windows users cannot complete this path; Git Bash does not provide fcntl to Windows Python. Add an explicitly selected OS/environment (custom dropdown), PowerShell setup + undo with private ACLs, existing-settings merge/backup and hidden key entry. Preserve default macOS/Linux flow. Acceptance: actual Windows CI/user smoke for setup, repeat setup, rotation, undo preserving unrelated edits and credentials; separate WSL validation; OS labels never imply untested support. Root has verified official `%USERPROFILE%\.claude\settings.json` guidance. No Windows run performed here.

2. **P1 / S–M: One-time token and connection steps are out of order.** Source-confirmed UX issue/inferred impact, no production issuance performed: `frontend/src/portal/PortalApp.tsx:78–84,110–118`. The token is rendered after the two-column access/setup grid, which stacks on mobile, and issue/rotate sets state without focus/scroll announcement. Setup is fully shown even pending approval. A newly issued token can be below lengthy instructions while the installer asks for it. Use a state-driven sequence (request → approval → save token → configure → verify), put one-time secret beside the issuance action, announce/focus its region, and keep optional instructions collapsed. Acceptance: on 390px viewport approved/newly-issued token is visible and keyboard reachable without searching; no secret in setup commands, telemetry or persisted client state; existing active members still get immediate setup/rotation access.

3. **P1 / M: Request scope is not consistently represented.** Confirmed code: `RequestExplorer.tsx:26–28,54,69,74–75`, `search.ts:3,12–22`. Exact-ID search is still bounded by default seven days. Custom dates change main results, but auxiliary tables still query only `days`; custom selector still displays a preset value under a custom label. Filtered drilldowns can therefore show adjacent, differently scoped totals. Existing explanatory copy helps but does not make the cohorts identical. Show visible applied-filter/date chips, a custom-window value, explicit scoped vs workspace section titles, and a helpful out-of-window exact-ID result affordance. Prefer demand-loaded separate workspace aggregates over silently changing API semantics. Acceptance: custom metrics drilldown, browser back/forward, refresh and paging preserve an explicit scope; no-result UI distinguishes date-bound search from missing/expired capture; dates validated against server 365-day/min-max constraints before generic 400 errors.

4. **P1 / M: Debugging requires manual joins between views.** Source-confirmed: `RequestExplorer.tsx:70,75` omits request ID/provider from result identity and renders access IDs as plain text; `Metrics.tsx:29` errors are static rows; `Management.tsx:22,56` member/account rows have no request links; search expects member IDs at `RequestExplorer.tsx:43`. Add compact copyable request IDs and provider context, member/key/account → scoped requests links, error-row → state/status/window links, and access-attempt → detail or explicit rejected/no-capture state. Reuse `openRequestScope` (`search.ts:34`) and keep Admin as the authority. Acceptance: one click from member or error cohort to matching requests, copyable correlation IDs without opening bodies, retained filters when returning; rejected attempts never imply a captured request exists.

5. **P2 / M: Request summary eagerly fetches bodies and presents metadata as JSON.** Confirmed source, production payload size intentionally unmeasured: `RequestExplorer.tsx:80,86–94`; `JdbcRequestQuery.java:63–64` joins body/header fields for detail. Even Summary parses/downloads all retained body/header fields, then hides them. Build typed summary DTO + labeled facts (outcome, duration, model/member, upstream ID, capture/usage coverage), lazy sections for authorized input/output/headers, preserve paged events/export and existing redaction. Acceptance: opening Summary transfers no body/header fields; tab navigation cancels superseded loads; retention/missing states remain explicit; large-capture fixture proves bounded rendering. This improves ordinary debugging without reducing the administrator's authorized access.

6. **P2 / S–M: Route/detail keyboard focus is incomplete.** Source-confirmed: `AdminApp.tsx:30–35` changes route/title but does not move/announce main heading; `RequestExplorer.tsx:39–40,83,87` focuses detail when opened but closes without restoring the invoking Inspect control. Keyboard/screen-reader users can lose their location. Save trigger ref and restore it on close; focus/announce page heading after client navigation; retain skip link. Custom Select already supports arrows/typeahead/Escape/roving options (`ui.tsx:69–100`), and live Escape focus restoration passed—do not replace with native selects. Acceptance: complete keyboard-only route → filters → inspect → close → paging flow; screen-reader smoke; no focus jumps during refresh. Browser accessibility integration is currently weaker than helper tests (`frontend/tests/admin.test.mjs`, `browser-layout.js`).

7. **P2 / M: Graphs need better investigation semantics before more decoration.** Confirmed source: `Charts.tsx:5,38–49`, `Metrics.tsx:18,27–28`. Color palette repeats after six model series; paths have no dash/visibility controls, multi-day ending axis labels omit date, no sample count accompanies timing percentiles, chart observations do not drill into time intervals. Existing keyboard inspection, table alternative and gap handling are strengths. Add selectable model series with non-color differentiation, date/timezone endpoints, sample count where server supplies it, and explicit selected-interval search action. Acceptance: seven-series synthetic fixture remains distinguishable; single sample/gaps/zero observations are honest; keyboard and table give same values; drilldown carries exact interval/model. Current live seven-day data was small, so this is usability/headroom, not measured rendering failure.

8. **P2 / M: Admin authority is clear but spread across three disconnected directories.** Confirmed source: `Management.tsx:7–68`. Members/keys, access requests, and accounts/sessions each expose different pieces; account directory stops at latest 100 matches, action log latest 50 exact-action matches, and IDs in action log are raw. Build linked member/account summary with permission/action scope, key status, limit editor, sessions and related audit action links; use a custom action selector populated by defined actions and cursor paging when scale merits it. Preserve explicit revoke vs session signout semantics already written in UI; do not add role delegation/second administrator. Acceptance: admin can trace request → account → key → action and see why controls are available without copying UUIDs; action detail clearly states affected identity and expected impact.

9. **P2 / S then measurement-gated M: Remove avoidable reads before adding capacity.** Measured: Explorer immediately fetches search, analytics and access (`RequestExplorer.tsx:26–28`), including 98 KB decoded access response for 50 rows although only five columns render. Audit SQL selects all columns (`JdbcAuditStore.java:61–62`). Lazy-load auxiliary panels and project the access DTO to visible metadata; measure again. Route code apart from guide is eagerly imported (`AdminApp.tsx:5–13`), but initial code is modest; chart table repeatedly finds points (`Charts.tsx:49`) but current buckets are small. Define typed feature API contracts and separate transport/hooks/components by responsibility as these features change (SOLID); avoid broad rewrite. Acceptance: a basic search only requests search until ancillary panel opens, no behavioral regression, navigation/payload/interaction measures improve; keep cancellation and no-store semantics. Do not add a Coder workspace from this evidence.

## Measured baseline and limits

Two fresh browser contexts on the already-running owned Chrome, no throttling, not a benchmark/p95. Desktop 1440×1000; mobile 390×844. First metrics navigation: TTFB ~440 ms, DOMContentLoaded/load ~884 ms; admin JS 75,918 decoded / 22,280 transferred bytes; shared React/API JS 225,782 decoded / 70,715 transferred bytes; CSS 15,104 decoded / 3,981 transferred bytes. Session 353 ms; first metrics 100 ms (subsequent metrics 384 ms/505 ms across 24h/7d). Seven-day metrics payload 8,029 decoded bytes; traffic path strings ~2.5 KB each, timing path strings ~0.3 KB each. No page errors; no horizontal document overflow at tested widths. Mobile nav intentionally horizontally scrolls. Connection first command block 331 px tall and copy action at y~550. Explorer loaded 25 rows: search 535 ms/24,661 decoded bytes; analytics 246 ms/3,645 bytes; access 341 ms/98,082 bytes. Advanced filters have 11 inputs and 5 custom selects. No raw values logged. Browser API timings include public-tunnel/network latency; cannot attribute latency to app/DB without server timing/traces.

Collect next: read-only repeated 1h/24h/7d timing, server/DB timing correlation, device-throttled LCP/INP/long tasks, actual large-series/capture fixtures locally, full keyboard/screen-reader run, Windows+WSL validation and onboarding completion feedback. Never send inference solely to make graphs look populated. Justify another workspace with sustained measured CPU/memory/IO/DB/Kafka contention and a before/after placement hypothesis, or a separately chosen isolation/recovery objective with a verified failure domain.

Defer broad component-library/router replacement, client cache of private captures, full-text prompt search, virtualization for current 25-request pages, WebSocket live dashboards, more charts without a question, splitting Coder infrastructure, and role-delegation redesign. Preserve dark-only styling, custom dropdowns, honest missing-data semantics, administrator authority, private keys and reversible setup.

Histogram/phase instrumentation and source-stamped headroom should precede capacity decisions; available host memory/low load and frontend size provide no present reason for another workspace.
